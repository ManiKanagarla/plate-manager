SECTION 1: WHAT IS THIS APP?
----------------------------------------------------------------

This is a web app built for your paper plate business to replace
phone notes. It helps you track:

  - Customers (name, phone, location, address, map link, rate)
  - Daily Sales (bundles sold, to whom, amount, paid/pending)
  - Stock Purchases (stock number, source, cost, transport)
  - Monthly Reports (revenue, pending, stock summary)

Live Link: https://manikanagarla.github.io/plate-manager/

This link works on any phone, tablet, or laptop.
All data syncs instantly across all devices.

SECTION 3: WHAT IS FIREBASE AND WHY WE USED IT
----------------------------------------------------------------

WHAT IS FIREBASE?
  Firebase is Google's free database service.
  It stores your app's data (customers, sales, stock) safely
  on Google's servers — so data is never lost.

WHY NOT JUST SAVE IN THE BROWSER?
  Browsers have something called "localStorage" which saves
  data on one device only. Problems with that:
    - Data is lost if browser cache is cleared
    - Data doesn't sync to other phones/laptops
    - Not a real database — just temporary storage

  Firebase solves ALL of these problems.

HOW FIREBASE WORKS:
  Your App (browser)
       |
       | when you add a customer / sale / stock
       v
  Firebase Firestore (Google's Database Server)
       |
       | instantly syncs to
       v
  All other devices using the same live link

  So if your friend adds a sale on his phone, you can see it
  immediately on your laptop — in real time.

FIREBASE PLAN WE ARE USING:
  Plan   : Spark (Free Plan)
  Cost   : Rs. 0 / month — completely free
  Limits : 50,000 reads per day
            20,000 writes per day
            1 GB storage

  For a small business with daily use, these limits are
  MORE than enough. A typical day might use 200-300 reads.

WHAT EACH LINE MEANS:

  apiKey            -> Password to access your Firebase project
  authDomain        -> For login/authentication (future use)
  projectId         -> Your unique Firebase project name
  storageBucket     -> For storing files (future use)
  messagingSenderId -> For push notifications (future use)
  appId             -> ID of your registered web app

THINK OF IT LIKE THIS:
  Config code = Address + Key to your database locker
  Without it  = App has nowhere to save data

SECTION 5: HOW THE APP IS ORGANIZED
----------------------------------------------------------------

The entire app is ONE file: index.html
This file contains:
  - Design (CSS) — colors, layout, buttons
  - Structure (HTML) — pages, forms, modals
  - Logic (JavaScript) — saving, loading, calculating
  - Firebase connection — reads and writes to database

The app has 5 sections (bottom navigation):

  1. HOME (Dashboard)
     - Today's bundles sold
     - This month's total bundles
     - Pending amount to collect
     - Total customers
     - Current stock status
     - Recent 5 sales

  2. CUSTOMERS
     - Add new customer
     - View customer details
     - Edit / Delete customer
     - See total sales per customer
     - See pending per customer

  3. SALES
     - Add daily sale
     - Customer auto-fills rate per bundle
     - Total amount auto-calculates
     - Mark as Paid / Pending / Partial
     - Payment mode: Cash / Phone Pay / UPI / Bank
     - Filter: All / Pending / Paid / Today / This Month

  4. STOCK PURCHASE
     - Add each stock (Stock 1, Stock 2... can have 2 per month)
     - Source location, supplier name
     - Purchase cost + Transport cost (auto calculates total)
     - Payment mode and payment date (how you paid supplier)
     - Billing Month — controls which month this stock appears
       under in reports (useful when stock arrives end of month
       e.g. June 30 stock → set Billing Month = July)
     - Return Bundles — optional, if you returned stock back
     - Auto-tracks how many bundles sold from each stock
     - Shows remaining bundles per stock

     MONTHLY EXPENSES (separate section below stock list):
     - One entry per month (not per stock)
     - Shop Rent, Petrol / Travel, Electricity Bill
     - Other Expenses + notes, Savings
     - Edit / Delete per month

  5. REPORTS
     - Month-wise summary — everything in ONE card per month:
       * Sales: transactions, bundles sold, revenue, collected, pending
       * Stocks this month: each stock with cost, sold/remaining
       * Monthly expenses: rent, petrol, electricity breakdown
       * Savings for the month

SECTION 6: DATABASE STRUCTURE (HOW DATA IS STORED)
----------------------------------------------------------------

Firebase stores data in 4 "collections" (like folders):

  CUSTOMERS collection:
    - name
    - phone
    - location
    - address
    - mapLink (Google Maps URL)
    - rate (price per bundle for this customer)
    - notes
    - createdAt / updatedAt

  SALES collection:
    - date
    - customerId (links to customer)
    - customerName
    - location
    - stockNumber (which stock it came from)
    - bundles (how many bundles sold)
    - rate (per bundle rate)
    - total (auto calculated: bundles x rate)
    - status (pending / paid / partial)
    - paymentMode (cash / phonepay / upi / bank)
    - paymentDate
    - amountPaid
    - notes
    - createdAt / updatedAt

  STOCKS collection:
    - stockNumber (1, 2, 3... 8, 9...)
    - date (actual purchase / arrival date)
    - billingMonth (e.g. "2026-07" — which month it shows in reports)
    - source (where it came from)
    - supplier (supplier name)
    - bundles (total bundles received)
    - purchaseCost (how much paid for stock)
    - transportCost (transport charges)
    - totalCost (purchase + transport, auto calculated)
    - paymentMode (cash / phonepay / upi / bank)
    - paymentDate (when payment was made to supplier)
    - returnBundles (how many bundles returned, optional)
    - notes
    - createdAt / updatedAt

  EXPENSES collection (monthly expenses — one entry per month):
    - month (e.g. "2026-07")
    - rent (shop rent amount)
    - petrol (petrol / travel cost)
    - electricity (electricity bill amount)
    - other (other expenses amount)
    - otherNotes (description of other expenses)
    - savings (savings amount for the month)
    - notes
    - createdAt / updatedAt
